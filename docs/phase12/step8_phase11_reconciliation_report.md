# Phase 12 Step 8 — Phase 11 Production Artifact Reconciliation

## 1. Executive Summary
This report summarizes the findings of a strict read-only forensic audit investigating a discrepancy between the documented Phase 11 GDP forecasting configuration and the physical serialized `best_t1_gdp_growth_model.joblib` artifact. The audit conclusively traces the root cause to a missing serialization step in the final `reproduce_t1_step10_best.py` script, which resulted in an older 29-feature pipeline remaining on disk. The Phase 12 Candidate B comparisons were determined to be methodologically sound, as they instantiated the correct 31-feature control model dynamically. 

## 2. Discrepancy Identified
During Phase 12 Step 7 (Production Readiness Audit), it was observed that the physical Phase 11 production artifact contained 29 features with `max_depth=6` and `l2_regularization=1.0`, contradicting the documented Phase 11 metadata (31 features, `max_depth=5`, `l2_regularization=5.0`). This immediately triggered a "PRODUCTION READINESS FAILED" status pending Step 8 forensic reconciliation.

## 3. Documented Phase 11 Configuration
**Verified from Phase 11 Documentation & Source Code (`t1_step11_model_metadata.json`, `reproduce_t1_step10_best.py`):**
- **Model**: HistGradientBoostingRegressor
- **Hyperparameters**: `max_depth=5`, `l2_regularization=5.0`, `learning_rate=0.05`, `max_iter=300`, `random_state=42`
- **Feature Count**: 31 (29 base features + 2 rolling features)
- **Validation RMSE**: 8.2853
- **Test RMSE**: 3.9113

## 4. Physical Serialized Artifact
**Verified from `best_t1_gdp_growth_model.joblib`:**
- **Hyperparameters**: `max_depth=6`, `l2_regularization=1.0`
- **Feature Count**: 29
- **Status**: Stale relative to official metrics.

## 5. Training-Code Provenance
**FACT VERIFIED FROM CODE:** 
- The 29-feature configuration was authored in `apps/api/ml/train_t1_baseline.py`.
- The 31-feature configuration was authored in `apps/api/ml/reproduce_t1_step10_best.py`.

## 6. Serialization Provenance
**FACT VERIFIED FROM CODE:**
- `train_t1_baseline.py` contains a valid `joblib.dump()` call which writes `best_t1_gdp_growth_model.joblib` to disk.
- `reproduce_t1_step10_best.py` successfully instantiated, trained, and evaluated the 31-feature model, but entirely lacks a `joblib.dump()` call. Consequently, the 31-feature model was never serialized.

## 7. Git/Repository Evidence
**FACT VERIFIED FROM ARTIFACTS:**
- The artifact modification times confirm that `best_t1_gdp_growth_model.joblib` was created significantly earlier (14:00) than the final `t1_step11_model_metadata.json` and `reproduce_t1_step10_best.py` files (18:22).

The reported Validation RMSE (8.2853) and Test RMSE (3.9113) exactly match the standard output generated by `reproduce_t1_step10_best.py`. The metrics are unequivocally derived from the 31-feature model, not the 29-feature physical artifact.

## 15. Root Cause Classification
> [!IMPORTANT]
> **RECONCILED — ARTIFACT/PIPELINE VERSION MISMATCH**
> The physical joblib is a stale output from a previous pipeline step due to an omitted serialization call in the final reproducible training script. The documented metadata and metrics correctly describe the final 31-feature model.

## 16. Final Reconciliation Decision
The provenance of the discrepancy is fully reconciled and understood. Phase 12 Candidate B experiments are structurally sound. However, the production environment requires a valid serialized artifact.
Phase 11 Production Status: **NOT CLEARED — PROVENANCE RECONCILIATION REQUIRED** (Re-serialization pending).
